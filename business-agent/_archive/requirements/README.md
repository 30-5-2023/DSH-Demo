# 需求澄清文档

存放业务 Agent 二次开发过程中产生的需求澄清记录。凡是「需求还没想清楚、需要和提出方确认」的内容，先在这里落一篇文档，确认后再开工；确认结果回写到 [../FEATURES.md](../FEATURES.md) 对应特性的「需求来源」一栏。

## 什么时候写

- 需求描述含糊，需要明确边界、优先级或验收标准时。
- 涉及外部业务系统的接口、字段、权限、凭据，需要逐条确认时。
- 出现方案分歧，需要在动手前记录取舍理由时。

## 命名与结构

```
requirements/
  0001-<kebab-case-标题>.md      # 需求澄清
  0002-<kebab-case-标题>.md
  TEMPLATE.md                    # 模板，不编号
```

- 编号四位递增，不复用已删除的编号。
- 文件名用小写英文 kebab-case，正文用中文。
- 每个需求文档只有一个「当前结论」小节；讨论过程写在「决策记录」里按时间追加。

## 写法约定

- 一段一行，不要硬换行。
- 待澄清问题用可勾选清单，每条都能回一个明确结论。
- 验收标准写成可执行、可观察的句子，不写「体验良好」这类无法验证的描述。
