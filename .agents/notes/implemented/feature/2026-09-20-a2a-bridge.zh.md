# Agent Note: 用于 Business Agent 互操作的 A2A bridge

Status: implemented

[English](2026-09-20-a2a-bridge.md) | 中文

## 问题

Business Agent 可以使用进程内及特定产品的 subagent 机制，但其他遵循标准的 agent 无法通过网络协议发现或调用它。Business Agent 也缺少一个面向模型的操作，不能通过 Agent Card URL 调用独立部署的 agent。因此，每个远端 agent 都需要定制集成代码，而且多次调用无法延续远端会话。

## 决策

`business-agent/` 下的 `@deepseek-ai/dsh-business-a2a-bridge` 插件为 A2A Protocol v1.0 和 v0.3 暴露一张 Agent Card 和一个 JSON-RPC 端点。官方 SDK 兼容层转换 v0.3 Card、方法名、payload、流事件和错误，bridge 内部仍使用 v1.0 类型。两个代际都支持消息发送、流式发送、Task 查询与 Task 取消。每个 A2A context 映射到一个持久化 DSH Session；同一 context 内的轮次串行执行，不同 context 之间进行有界并发。bridge 在提示 Session 之前持久化 context 和 Task 身份，使重试、取消和 Host 重启恢复使用稳定记录。

插件注册一个 `call_a2a_agent` 工具，接收 Agent Card URL 以及文本或 JSON 消息。客户端每次调用都重新解析 Card，允许内网部署使用私有 HTTP(S) 地址，强制执行超时、重定向、协议和响应大小限制，并且只返回紧凑的任务状态与输出。模型可见输入不接受出站凭据。

入站服务默认使用 A2A 专用回环监听器。部署可以让这个 A2A 专用监听器绑定 `0.0.0.0`，而不暴露共享 DSH Web 监听器。部署在运行时提供声明的 `publicBaseUrl`，因此容器和主机地址不会进入镜像，`0.0.0.0` 也不会成为客户端 URL。单个异步 Cordis effect 持有仓库恢复、监听器启动、出站工具注册与清理，因此启动期间发生销毁时不会留下仍在运行的监听器或仓库。仍可通过具名环境变量启用 Bearer 认证，但预研部署可不配置认证。日志与协议失败信息不包含授权值、完整提示词、推理、工具调用或完整远端响应正文。

此决策补充现有的 [subagent 能力](2026-06-21-subagent-capability-seam.zh.md)：subagent 提供方协调由本地组合选择的子 agent，而 A2A 为独立部署的 agent 之间提供基于标准的发现和调用。

## 曾考虑的替代方案

**把 A2A 实现为另一个具名 subagent 提供方。** 这可以复用本地委派词汇，但会把 A2A 发现、Task 查询、流式传输和持久化 context 语义隐藏在一次性子 run 抽象之后。因此 bridge 自行负责协议生命周期，并暴露一个明确的出站工具。

**暴露自定义内部 HTTP 端点。** 更小的请求/响应 API 实现更快，但每个对端都需要定制适配器，而且无法使用官方 A2A 客户端。因此 bridge 使用官方 SDK 和 A2A v1.0 JSON-RPC 绑定。

**暴露多个 agent 或进程内注册表。** 注册表会在第一条可互操作路径出现前引入路由、命名和策略问题。一个进程只声明一张可配置 Agent Card；需要不同 agent 的部署运行不同组合。

**强制 HTTPS 并拒绝私有地址。** 面向公网的默认规则会阻止所需的内网 URL-only 部署和本地双实例测试。bridge 允许私有 HTTP(S) URL，拒绝嵌入凭据和不安全重定向，并把 TLS 终止交给部署基础设施。

**让共享 Host 监听器绑定所有接口。** 这样可以减少监听器组件，但也会暴露 Web UI 和其他无关 Host 路由。专用监听器只提供 Agent Card 发现与已配置的 JSON-RPC 路由。

**要求所有内网部署必须使用反向代理。** 代理仍适合 TLS 与生产策略，但将其设为强制条件会阻塞所需的直接预研路径。运行时监听器接收部署提供的公开 URL，后续可以置于代理之后而无需修改镜像。

## 验证

- 官方 A2A v1.0 客户端纵向测试会发现 Agent Card，并在 Loader 组合的 Business Agent 上完成同步发送、流式发送、Task 查询、取消、context 延续和重启恢复。
- store 与 executor 测试固定 Session 复用、中断 Task 恢复、重复消息幂等性、取消竞态、流断开、格式错误内容、有界并发和完全停稳的清理。
- client 与工具测试固定仅凭 URL 的调用、文本与 JSON 结果、Card 重新获取、安全失败、重定向、超时、取消和响应大小限制，且不提供出站授权输入。
- 精确版本互操作测试在两个方向使用 Python `a2a-sdk==0.3.2`，覆盖旧版发现、流式传输、查询、取消和 v1.0 不降级；Windows PowerShell 5.1 回归测试验证缺少包元数据时能进入安装流程且不会触发原生命令错误。
- `business-a2a-call` Session 记录固定模型可见工具 schema、生产出站调用路径、持久化工具事件、紧凑结果，以及不包含模型 reasoning 与凭据这一事实。

## 后果

遵循标准的对端无需定制适配器即可发现并调用 Business Agent；Business Agent 也可仅凭 Card URL、消息和返回的 context id 延续远端 A2A 对话。bridge 在 DSH Session 轮次之外增加持久化协议记录和第二套生命周期；品牌化标识符、按 context 调度、持久化准入和竞态覆盖可防止取消无关轮次、重复终态和重启后遗留状态。

允许私有 HTTP 端点意味着按设计接受内网传输风险和服务端请求伪造风险。部署需控制哪些模型与用户可以调用该工具；fetch 策略仍拒绝凭据、fragment、非 HTTP 协议、降级重定向、无限重定向、超时和过大正文。

可选 Bearer 认证在配置后只保护入站 JSON-RPC 路由，不提供按用户身份、出站凭据、双向 TLS 或授权策略。未认证的通配监听器会接受任何可访问其端口的调用方，只适合边界明确的预研环境。生产策略不属于当前互操作路径。
