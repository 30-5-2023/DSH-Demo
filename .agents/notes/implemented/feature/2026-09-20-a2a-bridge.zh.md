# Agent Note: 用于 Business Agent 互操作的 A2A bridge

Status: implemented

[English](2026-09-20-a2a-bridge.md) | 中文

## 问题

Business Agent 可以使用进程内及特定产品的 subagent 机制，但其他遵循标准的 agent 无法通过网络协议发现或调用它。Business Agent 也缺少一个面向模型的操作，不能通过 Agent Card URL 调用独立部署的 agent。因此，每个远端 agent 都需要定制集成代码，而且多次调用无法延续远端会话。

## 决策

`business-agent/` 下的 `@deepseek-ai/dsh-business-a2a-bridge` 插件为 A2A Protocol v1.0 和 v0.3 暴露一张 Agent Card 和一个 JSON-RPC 端点。官方 SDK 兼容层转换 v0.3 Card、方法名、payload、流事件和错误，bridge 内部仍使用 v1.0 类型。两个代际都支持消息发送、流式发送、Task 查询与 Task 取消。每个 A2A context 映射到一个持久化 DSH Session；同一 context 内的轮次串行执行，不同 context 之间进行有界并发。bridge 在提示 Session 之前持久化 context 和 Task 身份，使重试、取消和 Host 重启恢复使用稳定记录。

插件注册 `call_a2a_agent`，接收 Agent Card URL、文本或 JSON 消息和可选本地文件。客户端每次调用都重新解析 Card，允许内网部署使用私有 HTTP(S) 地址，强制执行超时、重定向、协议、响应大小和文件大小限制，并返回紧凑的任务状态、输出和本地化文件路径。模型可见输入不接受出站凭据。单独的 `publish_a2a_file` 工具让入站 Task 可以把本地文件的稳定快照显式附加到完成 Artifact。

入站 A2A 发布窗口会观察通用 `present` 工具产生的持久化 `deliverables/presented` 事件。它只记录正在执行该 Task 的精确 Session 的声明，在 turn 成功结束后依次生成快照，并把它们作为 FilePart 附加在文本或 JSON 输出之后。快照或 Part 转换失败会让 Task 失败且不产生不完整 Artifact。同一已存储文件同时通过 `present` 和 `publish_a2a_file` 声明时只会出现一次；普通 Web Session 不属于 A2A 发布窗口。

受支持的文件 wire 格式是 Python `a2a-sdk==0.3.2` 文件 Part。不超过配置内联阈值的文件使用 `FileWithBytes`；只有专用监听器可以提供下载时，更大的文件才使用 `FileWithUri`，共享监听器模式会以 `A2A_FILE_URL_UNAVAILABLE` 拒绝它们。每个本地、内联或下载文件都先由现有 DSH attachment 服务存储。单独的 version-one `a2a_bridge_file_links` storage domain 只持有随机 256-bit 下载 token、Task 所有权、attachment 引用、media type 和过期时间，不会复制或删除 attachment bytes。远端输出文件通过已挂载的 attachment provider 本地化，并在工具结果中返回而不嵌入其 bytes。

入站服务默认使用 A2A 专用回环监听器。部署可以让这个 A2A 专用监听器绑定 `0.0.0.0`，而不暴露共享 DSH Web 监听器。同一个专用监听器提供不透明的 `GET` 和 `HEAD` 文件 URL；共享监听器永远不会暴露这些 URL，range 请求会被拒绝，过期会撤销 bridge 访问。部署在运行时提供声明的 `publicBaseUrl`，因此容器和主机地址不会进入镜像，`0.0.0.0` 也不会成为客户端 URL。单个异步 Cordis effect 持有仓库恢复、监听器启动、出站工具注册与清理，因此启动期间发生销毁时不会留下仍在运行的监听器、下载流或仓库。仍可通过具名环境变量启用 Bearer 认证，但预研部署可不配置认证。日志与协议失败信息不包含授权值、完整提示词、推理、工具调用、完整远端响应正文或不必要的下载 token。

入站 Session 调用 `ask_user_question` 时会在实时执行器中暂停，同时其 Task 持久化记录 `input-required`。状态 Message 包含一个 TextPart，以及由 `urn:deepseek-harness:a2a:input-required:v1` 标识的 DataPart。同一 Task 上的续接接受两类答案：一类是由 `urn:deepseek-harness:a2a:input-response:v1` 标识且为每个待回答问题提供一项答案的 DataPart，另一类是回答第一个问题的非空 TextPart。无效答案保留待回答状态并给出安全诊断。FilePart 可以作为说明与 interaction 一起提供，但不能回答问题。v0.3 客户端通过 `tasks/get` 查询状态；bridge 不会虚构 `message/get` 方法。

待回答问题刻意保存在内存中，因为实时 `ask_user_question` promise 及其 Session 执行栈不可序列化。它会保留上下文串行锁和一个有界并发槽位，直到收到答案、取消、关闭或达到请求截止时间；Bundle 默认值为五分钟。启动过程会把中断的待处理 Task 标记为失败，而不会假装能够恢复。宿主范围的问题监听器使用 `global` 和 `prepend`，因此会在普通 UI 回答器之前观察有作用域的问题；但它只认领具有开放 A2A Task 窗口的精确实时 Session id，并立即委托所有无关请求。

对于出站调用，`call_a2a_agent` 把待处理状态作为 `interaction` 与其 `task_id` 一起返回，把随附的 FilePart 物化到 `files`，并在下一次调用中接受该 `task_id`。因此，答案会继续同一远端 Task，而不是开始另一段对话。已完成、失败和取消的结果不含 `interaction`，并保留现有输出与安全失败字段。

此决策补充现有的 [subagent 能力](2026-06-21-subagent-capability-seam.zh.md)：subagent 提供方协调由本地组合选择的子 agent，而 A2A 为独立部署的 agent 之间提供基于标准的发现和调用。

## 曾考虑的替代方案

**把 A2A 实现为另一个具名 subagent 提供方。** 这可以复用本地委派词汇，但会把 A2A 发现、Task 查询、流式传输和持久化 context 语义隐藏在一次性子 run 抽象之后。因此 bridge 自行负责协议生命周期，并暴露一个明确的出站工具。

**暴露自定义内部 HTTP 端点。** 更小的请求/响应 API 实现更快，但每个对端都需要定制适配器，而且无法使用官方 A2A 客户端。因此 bridge 使用官方 SDK 和 A2A v1.0 JSON-RPC 绑定。

**暴露多个 agent 或进程内注册表。** 注册表会在第一条可互操作路径出现前引入路由、命名和策略问题。一个进程只声明一张可配置 Agent Card；需要不同 agent 的部署运行不同组合。

**强制 HTTPS 并拒绝私有地址。** 面向公网的默认规则会阻止所需的内网 URL-only 部署和本地双实例测试。bridge 允许私有 HTTP(S) URL，拒绝嵌入凭据和不安全重定向，并把 TLS 终止交给部署基础设施。

**让共享 Host 监听器绑定所有接口。** 这样可以减少监听器组件，但也会暴露 Web UI 和其他无关 Host 路由。专用监听器只提供 Agent Card 发现与已配置的 JSON-RPC 路由。

**要求所有内网部署必须使用反向代理。** 代理仍适合 TLS 与生产策略，但将其设为强制条件会阻塞所需的直接预研路径。运行时监听器接收部署提供的公开 URL，后续可以置于代理之后而无需修改镜像。

**把所有文件编码为内联数据。** 内联 base64 很简单，但会放大 JSON body，并迫使大文件进入内存。配置阈值让小文件保持自包含，并让更大的文件通过有界流和限时 URL 传输。

**通过 A2A 发送本地文件系统路径。** 路径只对持有它的机器有意义，而且会在不传输 bytes 的情况下泄露文件系统布局。bridge 在本地解析路径，把内容快照到 attachment，并且只发送 bytes 或 HTTP URL。

**要求每次成功调用 `present` 后再调用 `publish_a2a_file`。** 两次声明会让 Web 与 A2A 交付产生分歧，并使已完成 Task 漏掉已经向用户交付的文件。bridge 把持久化交付事件作为发布声明，同时保留 `publish_a2a_file` 以支持 A2A 专用输出。

**在重启后序列化并恢复待回答问题。** 这种方案可以在调用方决策期间释放进程所有权，但持久化 Task 记录无法重建实时 Session 执行栈或 `ask_user_question` 背后的任意工具续接。bridge 会记录协议状态、把真实续接保留在内存中，并在重启时让中断的 Task 失败。

**让普通 UI 问题回答器先观察 A2A 问题。** 这种方案可以保持普通监听器顺序，但 UI 回答器可能在 A2A 调用方收到 `input-required` 前认领或排队该问题。bridge 会先接收问题，并通过精确的 Session 与 Task 窗口身份委托它不持有的所有问题。

## 验证

- 官方 A2A v1.0 客户端纵向测试会发现 Agent Card，并在 Loader 组合的 Business Agent 上完成同步发送、流式发送、Task 查询、取消、context 延续和重启恢复。
- store 与 executor 测试固定 Session 复用、中断 Task 恢复、重复消息幂等性、取消竞态、流断开、格式错误内容、有界并发和完全停稳的清理。
- client、文件传输和工具测试固定文本与 JSON 结果、有序本地文件输入、raw 与 URI 输出本地化、精确 origin 和重定向策略、大小阈值、共享模式 URI 拒绝、Task 窗口身份、经包装的上传诊断、Card 重新获取、超时、取消和失败清理，且不提供出站授权输入。
- publication 与 executor 测试固定通用 `present` 事件捕获、非 A2A Session 隔离、有序快照、FilePart 输出、重复抑制，以及自动发布失败时 Task 失败且不产生不完整 Artifact。
- interaction 编解码、broker、executor、request-handler、生命周期和纵向测试固定 schema 校验、结构化与纯文本答案、无效答案重新发布、精确 Session 所有权、监听器委托、通过 `tasks/get` 查看状态、同一 Task 续接、保留并发槽位、超时、取消、关闭和重启失败。
- 精确版本互操作测试在两个方向使用 Python `a2a-sdk==0.3.2`，覆盖 input-required 续接、interaction FilePart 物化、恰好 1 MiB 的 `FileWithBytes`、1 MiB 加一 byte 的 `FileWithUri`、文件名、media type、Part 顺序、SHA-256、旧版发现、流式传输、查询、取消和 v1.0 不降级。`pwsh -NoProfile -File business-agent/verify-a2a-python-v032.ps1` 持有精确安装版本检查；Windows PowerShell 5.1 回归测试验证缺少包元数据时能进入安装流程且不会触发原生命令错误。
- `business-a2a-call` Session 记录固定模型可见输入 schema 中的 `task_id`、模型可见工具结果中的 `interaction`、一次确定性的 input-required 响应、结构化答案、同一 Task 完成、持久化工具事件，以及不包含模型 reasoning 与凭据这一事实。

## 后果

遵循标准的对端无需定制适配器即可发现并调用 Business Agent；Business Agent 也可凭 Card URL、消息、可选文件、返回的 context id 和返回的 Task id 延续远端 A2A 对话或回答问题。bridge 在 DSH Session 轮次之外增加持久化 Task 和文件链接记录；品牌化标识符、按 context 调度、持久化准入、attachment 快照和竞态覆盖可防止取消无关轮次、重复终态、复用可变文件和重启后遗留状态。

agent 可以在 Web 与入站 A2A 工作中使用同一个 `present` 交付动作。A2A 调用方会以 FilePart 接收每个成功交付的文件，否则会收到明确的失败 Task；只在文本中提到路径不会传输文件。

input-required 等待会占用一个已配置的上下文槽位，且不能在进程重启后恢复。这个代价让精确的 Session 执行及其问题 promise 保持存活；同时，持久化 Task 状态让调用方可以观察等待，并在重启后收到明确失败，而不是看到貌似可恢复的遗留 Task。

允许私有 HTTP 端点意味着按设计接受内网传输风险和服务端请求伪造风险。部署需控制哪些模型与用户可以调用该工具；fetch 策略仍拒绝凭据、fragment、非 HTTP 协议、降级重定向、无限重定向、超时和过大正文。

可选 Bearer 认证在配置后只保护入站 JSON-RPC 路由，不保护 capability-token 下载，也不提供按用户身份、出站凭据、双向 TLS 或授权策略。未认证的通配监听器会接受任何可访问其端口的调用方，泄露且未过期的文件 URL 会把文件 bytes 授予其持有者。这种模式只适合边界明确的预研环境。生产授权不属于当前互操作路径。
